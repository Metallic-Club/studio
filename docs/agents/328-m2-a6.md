- Messages: `ClientMsg` kinds 1-5, `ServerMsg` kinds 1-11, `PROTOCOL_MINOR = 0`. Frames `[kind][source][varint

- Hostile input: client frames over 64 KiB and datagrams over 1,200 bytes are refused before reading; the declared
  body length must match exactly; every postcard body must be consumed exactly; postcard preallocation is bounded by
  the bytes left; `NetValue` has a hand-written `Deserialize` that caps table nesting at 32 (a derived one overflows
  the stack on a 60 KB frame of nested tables); join snapshots inflate at most 16 MiB with a zstd window of at most
  16 MiB; bit readers check length before every read and require only zero padding to be left; quantizers map NaN
  to 0 and clamp infinities.
- `ClientMsg`'s `Debug` redacts the Hello ticket.

## Rulings (lead or mine)
- Lead: `registry_hash` is `[u8; 32]`; `Create.class` and property indices are plain `u16`; orientation goes through
  `metallic_core::CFrame` (`from_position_orientation`, `quaternion`, `from_quaternion`, `orientation_degrees`);
  `NetValue::Ref(Option<NetId>)`.
- Mine: encoders return `Result<Vec<u8>, WireError>` (the brief said `Vec<u8>`) so they can refuse what the peer
  would refuse (oversize, non-consecutive input ticks, tables too deep, non-finite own state) without `unwrap`.
- Mine: `ServerMsg::Create(Create)` wraps a `Create` struct so the join snapshot body (`Vec<Create>`) reuses it.
- Mine: server frames are capped at the transport's `MAX_SERVER_FRAME` (4 MiB), client frames at 64 KiB (join
  snapshots can exceed 64 KiB compressed).
- Mine: added `datagram_kind`, `encode/decode_unreliable_remote`, `compress_join`/`decompress_join`,
  `MAX_TABLE_DEPTH`, `MAX_JOIN_SNAPSHOT`, `MAX_INPUT_CMDS`, `MAX_UNRELIABLE_ARGS` (args postcard at most 1,000 bytes).
- Logging unknown kinds once is the connection handler's job (A7); the decoder only reports them.
